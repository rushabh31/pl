Architecture and supported features

PromptLab never runs your code: the runner gateway calls each service through its own contract, and the three planes inside the service steer and record model calls and data reads. Design details are in Architecture & design, sections 4 to 6.

User journey

Phase 0 users follow the middle row; from Phase 1, onboarded services feed real inputs and in-workflow experiments into the same path, and every result ends at the same decision and approval.

API flow: one trial of the refund service

One FORK trial of variant rules_v3 on test case refund-0031: intake and research replay from the memo store, the patched resolver and the responder go live to Gemini, and the result returns over SSE with no write. Step-by-step text is in the Integration cookbook, E3.

Dataflow: where a trial’s data lives

Test cases and prompt versions flow down from PromptLab, redacted spans and scores flow back up, and business data is only ever read; the production database sits outside every test path.
